Wir pflegen einen kleinen Satz eigener Agent-Skills für [pi](https://pi.farm)
und empfehlen einige aus Upstream. Jeder installiert sich mit einer Zeile:

```bash
curl -fsSL https://skale.dev/s/<name> | bash
```

Die eigenen Skills (`fetch-url`, `web-search`, `surf`) aktivieren über die
pi-Paket-Whitelist; externe (`impeccable`, …) über ihren Upstream-Installer.
Alle installierbaren Skills: [**/skills**](/skills/).

### `improve-architecture`: eine 7-Skill-Familie

Ein Install zieht [@mattpocock](https://github.com/mattpocock)s Architektur-Review-Familie: sieben Skills, die zusammenarbeiten.

- **`improve-codebase-architecture`**: Deepening-Chancen scannen, HTML-Report erzeugen, den gewählten Kandidaten im Grill-Durchgang ausfragen.
- **`codebase-design`**: das gemeinsame Deep-Module-Vokabular (Module, Interface, Tiefe, Seam, Adapter), das die anderen sprechen.
- **`domain-modeling`**: das Domänenmodell des Projekts pflegen (`CONTEXT.md`-Begriffe, ADRs).
- **`grilling`**: das kompromisslose Entscheidungsbaum-Interview im Kern des Grill-Schritts.
- **`grill-me`**: ein kompromissloses Interview, um einen Plan oder ein Design zu schärfen.
- **`grill-with-docs`**: Grilling plus Domain-Modeling, schreibt ADRs und Glossar nebenbei mit.
- **`batch-grill-me`**: ein kompromissloses Interview, das alle Grenzfragen auf einmal stellt, Runde für Runde.

Alle sieben installieren:

```bash
curl -fsSL https://skale.dev/s/improve-architecture | bash
```

Sie landen in `.agents/skills/` (pi liest das automatisch ein).

### `implement`: von Spec/Ticket zum Commit

Ein weiterer [@mattpocock](https://github.com/mattpocock)-Skill: Arbeit aus einer Spec oder Tickets umsetzen. TDD an vorab vereinbarten Nähten, wo möglich; regelmäßig typechecken, die volle Suite einmal am Ende, dann `/code-review` und Commit auf den aktuellen Branch.

```bash
curl -fsSL https://skale.dev/s/implement | bash
```

Nach dem Install lassen sich **Skills und Extensions** jederzeit mit `pi config` verwalten (interaktive TUI, Leertaste schaltet um, Tab wechselt den Scope) oder `pi config -l` (öffnet direkt im Projekt-Scope). Ein- und Ausschalten braucht keinen Re-Install.
